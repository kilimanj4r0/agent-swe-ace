# R0 — Legend & README

Shared reference for the results tables (files 2–7). All values are read from each run's `statistics.json` / `config.json` in `agent-swe-ace/data/` via `agent-swe-ace/scripts/compare_runs.py`, which computes pass@k with the **combinatorial estimator** `1 − C(n−c,k)/C(n,k)` (HumanEval; c = successful attempts out of n, macro-averaged over instances). Files 2–6 hold the filled results tables. File 7 (R6) is a **completed** paired significance-tests report (generated by `agent-swe-ace/scripts/q1_stat_tests_unified.py`; terms defined in the *R6 — significance tests* section below).

## Metrics & columns
| Column | Meaning |
|---|---|
| **pass@k** | combinatorial estimator `1 − C(n−c,k)/C(n,k)` (HumanEval), macro-averaged over instances; c = successful attempts out of n. At k=n it equals the fraction resolved in ≥1 of n attempts; for k<n it is the order-independent estimate of P(≥1 solve in k draws). **pass@1 == avg** (the per-attempt rate) by construction for multi-attempt val phases. |
| **iter0** | first-attempt resolution rate — raw ability before any skillbook accumulates. Distinct from pass@1: under the combinatorial estimator pass@1 equals the per-attempt avg, **not** the first-attempt rate. |
| **valB** | validation pass with empty skillbook (raw ability baseline) |
| **valS** | validation pass with the learned skillbook (full or retrieved) |
| **Δ** | valS − valB, in percentage points (skillbook benefit) |
| **avg / `p1 (avg)`** | per-attempt average resolution rate (mean of per-iteration rates) — **equals combinatorial pass@1**, so the two are shown once as a single `p1 (avg)` column (no separate `avg` column). It is per-attempt *reliability*; pass@5 (any-of-5) is *breadth* — they measure different things. |
| **Δavg** | valS p1 − valB p1 (= avg(valS) − avg(valB)), in pp |
| **sb-assisted** | # instances the skillbook contributed to resolving |
| **sk** | # skills in the learned skillbook |
| **temp** | agent-model sampling temperature (`agent...temperature`, default **0.0** = greedy). Column also appears as **Temperature** in R4. |
| **step** | max agent steps (model/tool turns) per attempt (`agent.step_limit`, default **100**) — caps trajectory length before a forced submit/abort. Also written **steps**. |

## Δ reference baseline (two framings)
The split025 tables (R2.3 / R3.2 / R4 / R5) report **5v5 Δ** by default: each run's valS minus its **own 5-attempt valB** (empty skillbook), a k-symmetric (5 vs 5) within-run control. For the 12 newer Q30 retrieval runs whose valB was *copied* from a matching `[orig]` run via `baseline_run_dir`, "own valB" is that copied 5-attempt baseline (still k-symmetric). QNext rows use each run's own valB (QNext is not in the aggregated reference).

Separately, **R6** runs a **60v5 block** (valS vs the shared 60-attempt aggregated reference `val_baseline_aggregated_split025_vpk5_qwen3` = **R1 Table 3**, low-noise) **and** a **5v5 block** (only the 12 `[orig]` runs, fresh valB). The two framings disagree: at pass@5 the Q30 full-book / retrieval Δp5 are **negative under 60v5** (vs the strong 38.7 baseline) but **~0 to positive under 5v5** (vs each run's own ~20–26 baseline). The tables use 5v5 for k-symmetry; see R6 §5 for the 60v5 pass@5 view.

## R6 — significance tests (file 7)
File 7 (`7_R6_val_repo_global_stat_tests.md`) is a **completed** report testing, per run, whether the learned skillbook beats the empty baseline on the split025 val set (113 instances, Q30 / qwen3). Generated by `scripts/q1_stat_tests_unified.py`. `valBL` = `valB`, `valSB` = `valS`.

### Designs — each row is one run × design (24 + 12 = 36 rows)
- **60v5** (24 rows, all runs) — run's 5-attempt `valSB` vs the **shared 60-attempt aggregated baseline** (`valBL60` = the Δ reference baseline above).
- **5v5** (12 rows, only the 12 `[orig]` runs) — run's `valSB` vs its **own fresh 5-attempt `valBL5`**, a k-symmetric (5 vs 5) within-run control.
- **`[orig]`** — the 12 early runs whose fresh val_baselines were pooled into `valBL60`; they get **both** designs. The 12 newer retrieval runs (bm25 / emb / random) copied valBL from a matching `[orig]` run, so they have no independent `valBL5` and are **60v5-only**.

### Tests (two-sided; Benjamini–Hochberg FDR per design family; bootstrap 10k, seed 42, α = 0.05)
- **Wilcoxon** / **paired t-test** — per-instance resolution-rate diff (`valSB − valBL`); the trustworthy rate (pass@1/avg) tests.
- **McNemar** — resolved-any (rate > 0) discordants; fair only in the 5v5 block (k-asymmetric in 60v5, where BL draws 60).
- **Bootstrap** — 95% CI on the mean diff (instance-level); CI excludes 0 ≈ significant at 0.05.
- **pass@5 (§5, 60v5 only)** — any-of-5 **breadth**: `valSB` solved-any-of-5 (binary, n=k=5) vs `valBL60` combinatorial `1 − C(60−c, 5)/C(60, 5)`.

### Headline
On the per-attempt **rate (pass@1/avg)** the skillbook is ≈ at/above baseline (nominal trends; 0 survive FDR). On **pass@5 (breadth)** it is **below** baseline (21/24 FDR-significant) — the skillbook raises reliability on instances it already solves but reaches fewer in 5 attempts. Full tables, conclusions, and caveats are in file 7.
